# Как использовался ИИ

Этот файл описывает работу над репозиторием. Он не заменяет личный ответ кандидата в анкете и не приписывает ему коммерческий опыт или исправления, которые он ещё не проверил.

## Где помог Codex

- Разобрал требования и предложил небольшую архитектуру: React-клиент, Fastify API и SQLite.
- Помог определить общие TypeScript-контракты, расчёты, валидацию дат и сумм, обработку повторной отправки.
- Подготовил интерфейс по предоставленному дизайн-референсу, включая адаптацию на телефон.
- Разделил реализацию серверной части, интерфейса и документации между агентами в общем рабочем каталоге.
- Подготовил тесты, команды сборки, Docker, автопроверки и документацию.

## Что нельзя принимать на веру

Факт генерации кода не подтверждает выполнение требований. Проверки в репозитории предназначены для следующих рисков:

- Комиссия может быть ошибочно принята за процент. Здесь она хранится и складывается как сумма в тенге.
- Календарный день может зависеть от часового пояса машины. Здесь он определяется началом поездки в UTC+05:00.
- Некорректная календарная дата может автоматически нормализоваться средствами JavaScript. API должен отклонять такие значения.
- Предварительный поиск поездки не защищает от одновременного добавления. Уникальность `id` обеспечивает SQLite.
- Новый UUID на каждую попытку запроса разрушает защиту от повторов. Клиент должен сохранять идентификатор одного намерения до подтверждённого результата.
- Красивый экран может скрывать неправильный расчёт. Связь интерфейса с API и значения из исходного задания проверяются отдельно.

## Что выявили ревью и запуск проверок

В этой сессии проверка сгенерированного кода выявила конкретные ошибки:

1. **Специальный путь SQLite.** В точке запуска сервера `resolve(':memory:')` превращал специальное имя базы в обычный путь к файлу. Добавлено отдельное условие: значение `:memory:` передаётся SQLite без преобразования. Причина обнаружена при ревью поведения конфигурации.
2. **Импорт шрифта.** Производственная сборка Vite обнаружила импорт `@fontsource-variable/inter/latin.css`, которого нет среди экспортов установленной версии пакета. Импорт заменён на существующий экспорт пакета. Такую ошибку выявляет реальная сборка, а не наличие зависимости в `package.json`.
3. **Повтор после отменённых правок.** При потерянном ответе правка поля и возврат к исходному значению сбрасывали идентификатор попытки. Итоговый запрос с теми же данными мог создать вторую поездку. Теперь ID меняется только при отправке действительно другого набора данных. Браузерный тест сохраняет поездку на сервере, обрывает ответ, меняет и возвращает комиссию, затем проверяет повтор с тем же ID и единственную запись.
4. **Названия полей при ошибке.** Текст проверки внутри `label` менял доступное название поля. Браузерный тест обнаружил это после некорректного времени окончания. Поля связаны со стабильными подписями через `aria-labelledby`; ошибка остаётся отдельным описанием.
5. **Исторический часовой пояс.** Форматирование через именованный часовой пояс могло расходиться с выбранным правилом фиксированного UTC+5 на старых датах. Форматирование времени приведено к тому же правилу, что и сервер, и проверено отдельным браузерным сценарием.

Это исправления, обнаруженные и внесённые во время совместной разработки с ИИ. Они не означают, что кандидат лично нашёл их; для анкеты следует описать собственное участие после изучения и проверки проекта.

Добавьте только реальный пример ошибки ИИ, которую вы лично заметили и исправили или осознанно приняли после проверки. Не стоит представлять потенциальные риски из списка выше как уже произошедшие ошибки.

Короткий личный ответ можно построить так:
