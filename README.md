# Смена

**Поездки и заработок за день.** Небольшой дневник смен водителя: выберите дату, посмотрите сводку и добавьте поездку. Сделан по тестовому заданию arqa.

## Что работает

- Переключение дней, список поездок и сводка: поездки, выручка, комиссия, наличные, карта и «на руки».
- Добавление через форму и API с проверкой суммы, дат, способа оплаты и комиссии.
- Повторная отправка с тем же идентификатором не создаёт дубль, включая одновременные запросы.
- SQLite сохраняет поездки после перезапуска; начальные данные загружаются из JSON один раз.
- Адаптивный интерфейс, состояния загрузки, пустого дня и ошибки.
- Тесты расчётов и API, браузерные проверки, Docker и автоматическая проверка сборки в GitHub Actions.

## Быстрый запуск

Нужны **Node.js 22.17+** и npm. Версия для разработки указана в `.nvmrc`.

```bash
npm ci
npm run dev
```

Откройте [http://localhost:5173](http://localhost:5173). Vite передаёт запросы `/api` серверу на порту `3000`.

По умолчанию открыт **1 октября 2026 года**: две поездки из задания, выручка **3 900 ₸**, комиссия **585 ₸**, наличные **1 500 ₸**, карта **2 400 ₸**, на руки **3 315 ₸**. Есть данные соседних дней; любая дата без поездок показывает нулевую сводку.

### Собранное приложение

```bash
npm run build
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). Один сервер отдаёт API и собранный интерфейс.

### Docker

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). База хранится в именованном volume: перезапуск и пересоздание контейнера сохраняют поездки. `docker compose down` останавливает приложение и сохраняет volume.

### Настройки

Значения по умолчанию позволяют запустить приложение без настройки окружения. Если нужно изменить их, скопируйте [`.env.example`](.env.example) в `.env` и отредактируйте значения: сервер читает этот файл при запуске. Доступные переменные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт API и собранного приложения |
| `HOST` | `0.0.0.0` | Адрес прослушивания сервера |
| `DATABASE_PATH` | `data/smena.sqlite` | Путь к SQLite |
| `SEED_FILE` | `data/trips.json` | Файл начальных поездок |

Начальные данные и маркер импорта записываются в одной транзакции. Повторный запуск не возвращает демонстрационные данные поверх пользовательских и не добавляет их заново. Для отдельной базы укажите другой `DATABASE_PATH`.

## Проверки

```bash
npm run check
```

Команда запускает тесты сервера, проверку TypeScript и производственную сборку. Браузерные проверки запускаются отдельно:

```bash
npx playwright install chromium
npm run test:e2e
```

Основные сценарии: сводка из задания, пустой день, граница суток, проверка входных данных, повторная и одновременная отправка, конфликт идентификаторов, сохранение после повторного открытия базы. Браузерные проверки проходят сценарий просмотра и добавления поездки.

В репозитории **19 тестов расчётов/API и 16 браузерных проверок** для компьютера и телефона. Последние включают потерянный ответ после сохранения, повтор с тем же ID, гонку при переключении дней и крупные суммы на экране шириной 320 px. GitHub Actions также собирает и запускает Docker-контейнер и проверяет его API и страницу.

## API

Сервер принимает и возвращает JSON. В разработке API доступен на `http://localhost:3000`, в Docker — на `http://localhost:8080`.

### `GET /api/days/2026-10-01`

```json
{
  "date": "2026-10-01",
  "timeZone": "Asia/Qyzylorda",
  "trips": [
    {
      "id": "t1",
      "start": "2026-10-01T03:10:00.000Z",
      "end": "2026-10-01T03:32:00.000Z",
      "amount": 2400,
      "payment": "card",
      "commission": 360
    },
    {
      "id": "t2",
      "start": "2026-10-01T04:05:00.000Z",
      "end": "2026-10-01T04:20:00.000Z",
      "amount": 1500,
      "payment": "cash",
      "commission": 225
    }
  ],
  "summary": {
    "tripCount": 2,
    "revenue": 3900,
    "commission": 585,
    "net": 3315,
    "cash": 1500,
    "card": 2400
  }
}
```

Дата имеет формат `YYYY-MM-DD`. Дата без поездок возвращает `200`, пустой `trips` и нулевые показатели. Некорректная дата возвращает `400`.

### `POST /api/trips`

```json
{
  "id": "demo-request-001",
  "start": "2026-10-01T10:00:00+05:00",
  "end": "2026-10-01T10:25:00+05:00",
  "amount": 2000,
  "payment": "cash",
  "commission": 300
}
```

Первое добавление возвращает `201` с телом `{ "trip": { ... }, "created": true }`. Повтор того же `id` и данных возвращает `200` с `created: false`. Тот же `id` с другими данными — `409`. Некорректные данные — `400`.

Идентификатор создаёт клиент **до первого запроса** и сохраняет при повторе. Для нового намерения добавить поездку нужен новый идентификатор, например UUID. Совпадение суммы и времени у разных идентификаторов не считается дублем: это могут быть две отдельные поездки.

### `GET /api/health`

Проверка доступности сервера, используется в том числе контейнером.

Контракты запросов и ответов находятся в [`shared/types.ts`](shared/types.ts).

## Правила расчётов и хранения

**День поездки** определяется временем начала в фиксированном часовом поясе **UTC+05:00**, который в приложении обозначен как `Asia/Qyzylorda`. Поездка через полночь относится ко дню начала. Часовой пояс компьютера не влияет на результат.

**Время** принимается в полном ISO 8601 с указанием секунд и явным часовым поясом (`Z` или `±HH:mm`); миллисекунды необязательны. Сервер проверяет существование календарной даты и порядок моментов времени, затем приводит их к UTC. Разные записи одного момента, например `08:10:00+05:00` и `03:10:00Z`, считаются одинаковыми при проверке повтора.

**Деньги** — целые тенге без дробной части. Сумма поездки от `1` до `1 000 000 000`, комиссия — от `0` до суммы поездки. `commission` — денежная сумма, а не процент. Итоги рассчитываются на сервере:

```text
выручка = сумма amount
комиссия = сумма commission
на руки = выручка − комиссия
наличные = сумма amount, где payment = cash
карта = сумма amount, где payment = card
```

Разбивка наличные/карта показывает валовую выручку до комиссии. Значение «на руки» отражает заработок после комиссии, а не фактический остаток наличных или доступность средств к выводу.

**Повторные запросы** защищены первичным ключом SQLite на `id`. При конфликте сервер сравнивает сохранённые и нормализованные данные запроса. Уникальность обеспечивает база, поэтому два одновременных запроса не могут создать две строки с одним идентификатором.

## Устройство проекта

```text
src/          React-интерфейс и стили
server/       Fastify API, валидация, расчёты и SQLite
shared/       Общие TypeScript-контракты
data/         Начальные поездки JSON
tests/        Тесты логики, API и браузерных сценариев
docs/         Скриншоты, решения по дизайну и описание работы с ИИ
```

Стек: **React, Vite 7, TypeScript, Tailwind CSS 4, Fastify 5**, встроенный в Node.js модуль `node:sqlite`. В производственной сборке фронтенд и API работают с одного адреса. SQLite подходит для небольшого приложения и не требует отдельного сервера базы данных.

В объём задания входят один водитель и локальное хранение. Авторизации, нескольких пользователей, внешних платёжных интеграций и реального вывода денег здесь нет. Формат API и правила расчётов можно расширить, если продукту понадобятся эти сценарии.

Визуальные решения по предоставленному референсу: [`docs/DESIGN.md`](docs/DESIGN.md). Использование ИИ и точки проверки: [`docs/AI_USAGE.md`](docs/AI_USAGE.md).
